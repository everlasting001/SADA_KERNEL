# Edition3 优化报告

日期：2026-11-14。工具：实际运行的 Windows Vitis HLS 2022.2 与 Vivado 2022.2。器件：`xc7z010clg400-1`。

**历史版本说明：本报告保留实验2使用16参考点时的结果。** 后续用户要求实验2改为32参考点，当前源码使用 `18_reference32`，新增结果见 [32参考点实验报告](REFERENCE32_REPORT.md)。下文的“默认版”“源码哈希”和配置2数据均指当时的 `13_insert_bram` 归档，不再指当前32参考点源码或更新后的 `report/`。

**默认采用 `13_insert_bram`，已写入 `Edition3/src/sada_kernel.cpp`。四种配置均通过C仿真、Verilog协同仿真和50 MHz独立IP布局布线。** 本轮优化时未修改Edition1、Edition2和用户提供的Edition3原报告；此后用户已将 `Edition3/report/` 更新为优化后的综合及仿真报告，顶层结果已核对一致。完整试验归档仍在 `optimization/trials/`。用户授权清理后，`report/experiment_3/syn/` 残留的10个旧分模块文件已删除，详见[清理记录](optimization/cleanup_legacy_reports.json)。

## 2. 保持了哪些条件

- 每次调用处理512点、96通道、一个时间步；公共16NN候选域和接口不变。
- 四组仍是：有符号 `Q-K` 最近8、XOR最近8、XOR全部16、XOR最近4＋密度Top-4。
- 所有既有数值类型和位宽保持不变；密度倒数、样本方差、整数开方、归一化、截断区间和PLIF公式未替换为近似算法。
- `reduce_reference_spikes()` 与 `update_plif()` 的计算源码保持不变。没有仅为XOR增加专属优化。
- 选点仍在PL内，每次调用都重新计算；未把密度预处理搬到PS，也未省略其成本。
- 四组正式对比统一20 ns目标周期、5.4 ns HLS时钟不确定度、器件、测试和实现原则。参考数改变时，缓存副本与参考bank数量按同一规则改变。

优化的是电路复用、等价Top-4实现和访存端口供给。HLS会据此重新调度、自动展开部分内层循环；这属于共同实现策略，不改变比较算子的数学定义。

本轮起点是初始Edition3的“归一化外层PIPELINE off”版本，已复现截图中的15,539 LUT、257,166周期。它与Edition2的21,354 LUT、217,310周期不是同一基线，不能混用。对Edition2而言，默认版HLS LUT减少66.8%、延迟减少5.9%；本报告主要使用更接近当前工作的Edition3起点作对照。

## 4. 为什么这些改动有效

### 4.1 让昂贵的电路复用

关闭原始密度、归一化和逐点选择的外层流水线，限制HLS为吞吐自动生成的大型组合网络和流水寄存器。单独这样做会变慢，05已经实际证明这个代价；不能只看LUT下降。

归一化II=8/16/32对应的除法流水结构资源相近。较大的II没有自动换成小型串行除法器，所以16、17没有成为更好的折中点。

### 4.2 用BRAM提供K读取端口

逐点计算需要读取8个或16个任意编号的K。把512个K全部分割成寄存器，会生成昂贵的随机读选择网络。06与12的计算周期相同，但LUT从27,679降到6,319，是本轮直接的对照证据。

默认版每个通道先顺序读取512个K：8参考复制到4份双端口BRAM，16参考复制到8份。参考槽 `r` 读取副本 `r/2`，每份最多承接两个读请求。参考编号按参考槽分bank，与这些读取端口配合。

代价是额外BRAM和每通道的缓存加载。默认版的局部点循环与加载循环均实际达到II=1，但**整个内核仍按通道、按阶段顺序执行**，不是每周期输出一个完整样本。

### 4.3 稳定Top-4减少选择时间

原版重复寻找四次最大未选分数；新版扫描其余12个候选，维护4个最佳项，四个比较位置展开。既保留前4个最近点，也保留所有密度同分的候选顺序。

这一步使12→13从266,342降到204,390周期，增加780个HLS LUT。只对4个最佳项做小规模展开，比对整片点云盲目展开更合适。

## 8. 工程边界与下一步

本轮完成了独立内核优化，**未完成上板系统**。Vivado为out-of-context流程，只有内部时钟约束；数组端口没有完整的外部输入/输出时序预算。必须在接入实际存储和控制系统后重新验证时序。

当前仍是 `ap_memory` 数组接口。膜电位 `[96][512]` 单份192 KiB，以及Q/K/V、距离、编号和输出的外部存储，不完整计入这里的BRAM。当前IP资源不能直接当作整套系统资源。

下一步按以下顺序进行：

1. 用真实16NN、Q/K/V和训练后的PLIF参数，对照软件，统计选点与阈值差异。
2. 保留PS逐步调用方式，设计AXI/DDR封装和状态缓冲；新样本初始化一次，跨时间步保留膜电位。
3. 完整系统实现后测PS可见延迟、DDR流量及板级功率；与本报告内核数字分开。
4. 若优化跨步选点缓存，需把一次密度选择成本计入整段序列，并统一四组计时边界。本版没有通过省略这部分获得收益。

本轮未缩减数值位宽、未替换密度数学公式。进一步压低DSP和宽除法开销，需要数值误差与真实模型精度评估，不能仅以综合资源下降为依据。
